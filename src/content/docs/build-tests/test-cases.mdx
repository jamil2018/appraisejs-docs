A test case is a single scenario composed of ordered template steps.

## Workflow context

Test cases are where reusable assets become a specific business scenario. Environments and modules still need to exist before you create a test case. From the test case form, you can create or select suites and tags, then build steps in the flow builder. When a step needs a locator, create it from the node addition sidebar or select an existing locator.

## Do this

1. Go to `Test Cases -> Create`.
2. Add title (min 3 chars) and description.
3. Select the module that owns the scenario.
4. Select an existing test suite or create one from the test case form.
5. Optionally select existing tags or create tags from the same flow.
6. Build the flow in the flow builder.
7. Add steps from the node addition sidebar.
8. Create or select locators from the node addition sidebar when a step needs one.
9. Fill required parameters for each step.
10. Save.

## Minimal example

- Title: `Valid login shows welcome banner`
- Module: `Authentication`
- Suite: `Auth Smoke`
- Tags: `@smoke`, `@auth`
- Steps: navigate, fill email, fill password, click submit, assert banner visible

## Flow builder tools

The refreshed flow builder keeps larger scenarios easier to create and review without turning the test case form into a separate product area.

### Blocks

Use blocks to group related nodes, such as login setup, form submission, and post-login assertions. Blocks make larger flows easier to scan and help reviewers understand which nodes belong to the same intent.

## What good looks like

- Keep one business outcome per test case.
- Use clear step labels and stable locator references.
- Use blocks when related nodes should be understood together.
- Use search before manually scanning a large flow.
- Use full-screen mode when the builder needs more working space.
- Use template test cases for repeated patterns.
