Software built by coding agents can drift between a request, a plan, implementation, and the evidence used to call it complete. <br/><br/>

You write scripts in one place, manage test cases in another, run them through a separate pipeline, and debug failures somewhere else. **The more your system grows, the more fragile and disconnected everything becomes.** <br/><br/>

AppraiseJS keeps that story connected. <br/><br/>

It gives agents a structured lifecycle for authoring plans and validations while keeping review, approvals, durable state, execution evidence, recovery, and completion gates visible to you.

---

AppraiseJS is a local-first quality operating system for agent-assisted software delivery. <br/><br/>

Your agent authors the plan, validations, and code. AppraiseJS binds them to the project, presents review gates, orchestrates evidence capture, and makes the path from original intent to completion inspectable. Visual test modeling and portable Playwright and Gherkin output remain part of that system.

---

> **Own your tests. Always.**  
> AppraiseJS generates real, portable test artifacts (Gherkin + Playwright) that can run outside the platform. No lock-in. No proprietary formats.

---

## How it works

At a high level, this is how you build and run tests in AppraiseJS:

1. Configure your environment.
2. Create a module for the product area you want to test.
3. Create a test case and choose or create its suite and tags from the test case form.
4. Build the scenario in the flow builder, creating needed locators from the node addition sidebar when a step needs one.
5. Use blocks, search, and full-screen mode to keep larger flows easier to review.
6. Run tests with flexible selection (by suite, tags, or specific cases).
7. Analyze results through a unified reporting system with all execution data in one place.

## Who AppraiseJS is for

- QA engineers tired of maintaining brittle, code-heavy test suites
- Developers who want fast test creation without boilerplate overhead
- Teams that need shared ownership across QA, dev, and product
- Organizations that want full control over their test artifacts (no vendor lock-in)
